# GUI:从调试页到桌面应用（2026-08-05）

## 目标与非目标

**目标**：`src/agentdeck/ui.py` 的 `_PAGE` 是一个完整的桌面应用品质界面，
AgentDeck 已实现的编排能力全部在里面**可用且真能操作**。

**非目标**：给现有调试页继续打补丁。8-05 上半天做了 6 刀增量（两栏、选择器、
卡片渲染、快捷键、注册表桥），结果是"越来越不难看的调试页"，不是应用。
user 的原话：**"我要完整的去模仿桌面版本去做，当然对应的功能也要是有的"**。
所以这份 spec 的前提是**重写**，不是继续修补。

不复制任何产品的品牌标识、商标字样或专有图标；做的是布局形态、导航结构与
品质标准。

## 三栏骨架

```
┌──────────────┬────────────────────────────┬──────────────┐
│ 侧边栏        │  Leader 对话主窗            │ 上下文面板    │
│              │                            │              │
│ + 新建任务    │  自然语言提问               │ 当前任务状态  │
│ 任务/会话列表 │  卡片内联渲染               │ runtime      │
│              │  控件即按钮                 │ 审批队列      │
│ 设置          │  composer + 后端选择器      │ 事件流        │
└──────────────┴────────────────────────────┴──────────────┘
```

## 已验证的数据事实（8-05 实测，不要重新推导）

| 事实 | 证据 |

| **注册表是 control_id 的权威来源** | 同一条命令在 `/api/controls` 里有 id；15 个卡片控件 15 个都能换到，零落空 |

| `plans.items[]` 的标题字段叫 **`task`** 而非 `goal` | **2026-08-05 订正**：原记为"没有标题字段、要动端点白名单"是错的。`project_view.plans.items[].task` 就是任务原文，workbench 载荷里已有，侧边栏**不需要新端点** |

## 铁律

1. **既有 4639 字节脚本块一个字节不碰**。控件按钮、inspect/execute、events
   游标都在里面，是已验证能用的执行面；重排布局时最容易顺手"整理"坏它。
   新逻辑一律写在自己的 script 里。
2. **GUI 只做契约消费方**。`enabled` / `blocker` / `safety` 一律照抄
   contract，前端不判断任何东西。今日实例：下拉里当前 provider 是灰的、
   理由写着 `already current provider`——那是注册表自己的状态流进界面。
3. **控件执行前用命令原文去注册表换 id**。查注册表不是绕过契约，正是消费它。
4. `inspect` 走 `/api/inspect`；`explicit_*` 走 `/api/execute` 的二步确认，
   对话框展示**完整命令原文**，取消即零执行。`delegated` 保持复制不可执行。
5. 每轮跑测试再提交；`tests/test_ui_server.py` 是端点契约的守门人。

## 建议顺序

1. **三栏骨架重写**——一次设计好，而不是从两栏长出来。
2. **右栏上下文面板**——把 runtime / 审批 / 事件做成与对话区一致的卡片风格。
3. ~~侧边栏任务列表~~——**已完成**（标题取 `plans.items[].task`，无需新端点）。
4. **新建任务入口**——`goal preview` → 确认屏 → `goal start`，两步确认
   一条不减。
5. **委托梯子**——人类门停下时，`delegation gate-preview` 的前缀梯子内联
   展开；**绝不推荐、绝不排序、绝不预选**（有回归钉断言渲染中无"建议/
   recommended/safe"字样）。这是 CLI 下八步恢复流程压成一步的地方，也是
   GUI 相对 CLI 唯一真正解锁的东西。

   **⛔ 2026-08-05 实测:该项被三重阻碍,需 user 决定后才能开工。**

   1. **够不着**。控件注册表 132 条、27 个 scope，**没有一条 delegation
      或 gate-preview**，所以 `/api/inspect` 走不通。要么把它加进 GET
      白名单（与加 `chat` 同类的决定，但**更小**——gate-preview 是纯只读，
      chat 是会写的），要么在 CLI 侧给注册表补一个 `scope=delegation`
      控件（契约改动）。
   2. **空态不是 JSON**。无人类门时它打印纯文本
      `no human gate in the run-loop host record (stopped_reason=…)`
      并**非零退出**；`run_cli_json` 期望 JSON，直接接进来会 500。
      接线时必须先处理这个降级路径。
   3. **无法验证**。当前项目没有人类门（宿主以 `budget_exhausted` 停止），
      造不出真实数据。对着猜出来的形状做渲染器，正是本 spec 开头警告过的
      那件事——所以不做。

   可行的验证路径：起一个真实走开段并让它撞上未委托的授权框（今天 round 1
   就是这样停的），届时 `gate-preview` 才有真实输出可渲染。

   **只暴露零 pane 读取的那一档**：`gate-preview` 默认读宿主记录（零 pane
   读取），`--agent` 会做实时 pane 扫描。若日后接线，只暴露默认档。

## 会碰到的已知阻碍

- ~~任务标题~~：**已解除**（字段是 `task`，见上表订正）。
- **会话线程化**：`chat_turns[]` 无 `plan_id`，左栏点任务只能切右栏上下文，
  对话本身分不了线。真要分线程是 state/契约改动。
- **工作目录切换**：`ui serve` 服务的是启动时 cwd 的项目；换目录是 server
  生命周期问题，且正是那一次目录信任点击该落的地方。
