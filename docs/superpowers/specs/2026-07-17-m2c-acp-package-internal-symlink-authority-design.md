# M2c ACP Package Internal Symlink Authority Design

**Date:** 2026-07-17
**Status:** Approved under the user's delegated M2c completion authority
**Milestone:** Phase 3 M2c real four-stage acceptance closure
**Scope:** M2c ACP package-tree authority and acceptance evidence only

## 1. Purpose

Frozen implementation
`582fc2c7f3b344b5310d254d017e461d68f806f6` safely derives the official ACP
entrypoint from sealed npm metadata and passed two complete suites. Before its
real preflight was started, the explicit installed-input audit found two npm
generated links inside the actual package:

```text
node_modules/.bin/node-which
  -> ../which/bin/node-which

node_modules/.bin/anthropic-ai-sdk
  -> ../@anthropic-ai/sdk/bin/cli
```

Both targets are regular executable files inside the same package tree. The
current complete-tree sealer rejects every symlink, so the official npm package
cannot establish authority. The designated preflight was not started and its
one-shot authority was not consumed.

This design accepts only the narrow package-internal symlink form generated by
npm while preserving non-following traversal, closed content identity, runtime
drift detection, and fail-closed execution.

## 2. North-star alignment

- AgentDeck validates the real installed ACP adapter rather than a rewritten
  copy or synthetic wrapper.
- The complete package remains content-addressed and auditable.
- Symlink metadata is identity evidence, not execution permission.
- The actual ACP entrypoint remains a non-symlink regular executable selected
  by `package.json`.
- preflight and live continue to consume one exact package authority.
- no install, upgrade, login, global change, PATH fallback, or user tmux access
  is introduced.

No production `src/agentdeck/**` behavior changes.

## 3. Alternatives

### 3.1 Exclude `node_modules/.bin`

Rejected. It would make the complete-tree claim false and permit unsealed
package mutations.

### 3.2 Allow only closed npm `.bin` symlinks

Chosen. A link is accepted only under `node_modules/.bin/`, only when its link
text is relative and stable, and only when lexical normalization resolves to a
regular file already present in the same sealed manifest.

### 3.3 Allow arbitrary internal symlinks

Rejected. It unnecessarily expands the accepted package language and makes
directory traversal, link chains, and platform behavior harder to audit.

## 4. Accepted symlink contract

A package symlink is valid only when every condition holds:

1. Its normalized manifest path has the form `node_modules/.bin/{command}` with
   exactly one non-empty final component.
2. `lstat` reports a symlink; traversal never calls `stat(..., follow=True)` on
   it and never recurses through it.
3. `readlink` returns a UTF-8 encodable, non-empty relative string with no NUL
   or backslash.
4. Lexical POSIX normalization begins at the link's parent, processes `.` and
   `..`, and never underflows the package root.
5. The normalized target path is a distinct manifest member of kind `file`.
6. The target is not a symlink, directory, special file, or link chain.
7. The target's ordinary package safety and runtime seal checks already pass.
8. Initial and final symlink `lstat` identity match, and two bounded `readlink`
   observations return the same text.

Absolute targets, root escape, missing targets, directory targets, link chains,
links outside `.bin`, nested paths below a `.bin` link name, invalid encoding,
or runtime drift return only `claude_agent_acp_package_invalid`.

## 5. Manifest and runtime identity

`_PackageManifestEntry` already has a generic `kind`. The accepted link is
represented as:

```json
{
  "path": "node_modules/.bin/node-which",
  "kind": "symlink",
  "size": 23,
  "content_hash": "sha256-of-utf8-link-text",
  "executable": false
}
```

`size` is the UTF-8 byte length of the link text, not target size.
`content_hash` binds the exact link text. The target file has its own independent
manifest row and content hash. The process-local runtime row stores the link's
device, inode, owner, mode, size, and mtime from `lstat`.

After the non-following scan finishes, a pure closure validator checks every
symlink row against the full manifest. The stable tree hash includes symlink
rows in normal sorted order.

## 6. Authority versioning

Accepting a new manifest member kind changes package authority semantics. The
new cross-process schema is:

```text
m2c-tool-authority/v3
```

The strict designated response becomes:

```text
m2c-live-preflight/v5
```

The public response shape remains closed and unchanged apart from these schema
versions. A v1/v2 digest or v3/v4 preflight cannot authorize this live node.

## 7. Controlled launcher

The generated mode-0500 ACP launcher must reproduce the same non-following
manifest rules:

- scan directories and regular files as before;
- record accepted `.bin` links through `lstat` plus stable `readlink`;
- never recurse or open through a link;
- validate lexical target closure against the completed manifest;
- compare the exact runtime and stable manifests with the admitted package
  authority;
- separately revalidate Node and the regular metadata-selected ACP entrypoint;
- execute only sealed Node plus that regular entrypoint.

Any difference exits `126` with empty stdout/stderr.
